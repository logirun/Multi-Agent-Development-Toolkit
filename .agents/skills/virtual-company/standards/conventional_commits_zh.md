# AegisFlow 中文结构化提交规范指南 (conventional_commits_zh.md)

> **“规范的代码历史是可信追溯的第一基石”**  
> —— 本指南规定了 AegisFlow 智能体在执行代码提交时必须遵守的中文结构化提交格式，受 Gate 2 门禁强制校验。

---

## 1. 提交信息结构标准

所有 Git 提交必须满足如下格式：

```
<类型>(<影响范围或模块>): <简明中文动宾描述>

[可选正文：详细说明变更背景、核心改动点与技术权衡]

[可选页脚：关联工单编号或通过门禁声明]
```

### 1.1 常用类型（Type）规范与中文范例：

| 类型代码 | 适用范畴 | 中文高质量范例 |
| :--- | :--- | :--- |
| `feat` | 新增业务功能、模块或服务接口 | `feat(用户鉴权): 实现基于 RSA-256 的 JWT 令牌签发与验签` |
| `fix` | 修复缺陷、逻辑漏洞或并发冲突 | `fix(状态引擎): 解决看板原子化写盘时的临时文件竞争缺陷` |
| `test` | 新增或补强自动化单元/回归测试套件 | `test(门禁守卫): 补充 pre-commit 物理拦截规则单元测试` |
| `docs` | 架构设计更新、接口说明或图谱同步 | `docs(架构指南): 同步更新活文档与 AST 代码结构地图` |
| `refactor` | 代码重构（不改变外部可观测行为） | `refactor(状态机): 优化工单状态迁移快照深拷贝内存开销` |
| `perf` | 性能调优（降低耗时或内存占用） | `perf(语法快筛): 利用 AST 缓存机制降低多文件遍历分析时延` |
| `style` | 格式对齐、标点空格（不改动逻辑） | `style(代码格式): 统一源码为 4 空格缩进并清理未用导入` |
| `build` | 构建系统、编译脚本或第三方依赖 | `build(依赖升级): 引入 cryptography 库用于 SHA256 签名` |
| `ci` | 流水线配置、自动化门禁测试脚本 | `ci(门禁流水线): 配置自动化多语言技术栈嗅探执行器` |
| `chore` | 例行维护、脚手架微调、配置文件 | `chore(脚手架): 补齐标准工程脚手架初始目录结构` |
| `revert` | 撤销或回滚先前的某次代码提交 | `revert(用户鉴权): 回退存在安全隐患的弱盐值哈希算法` |

---

## 2. 完整提交范文

```git
feat(用户鉴权): 实现基于 RSA-256 的 JWT 令牌签发与验签

- 新增 Token 签发与私钥解密验签核心模块，实现无状态身份认证
- 严格遵循 1:1 测试镜像原则，配套提供 tests/test_auth.py 测试套件
- 本地执行 AST 语法快筛通过，零括号解析与缩进语法错误

关联工单: TSK-1001 (Gate 2 静态审查通过)
```
